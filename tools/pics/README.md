# 翻卡配图管线（tools/pics/）

老曾 2026-09-20 的需求：「翻卡学点词模块，每个单词的左边或者右边放一个对应单词的图片，
这样有助于加强单词的记忆」。

## 为什么是 emoji 而不是照片

App 的硬约束是**单文件、零依赖、离线可用**（见 SKILL.md「注意」）。5000 个词要配真照片，
要么塞进同一个 HTML（体积爆炸）、要么走外链 CDN（断网 / 国内网络下大面积裂图）。
emoji 是系统自带的彩色图形字体，零体积、零请求、永远在，是目前唯一能同时满足
「每个词都有图」和「离线可用」的做法。

## 三个文件

| 文件 | 干什么 |
|---|---|
| `pic_map.json` | **人工核对过的图库（唯一事实源）**：`{"单词": "emoji"}` |
| `build_pic_map.py` | 把上表编译进 `index.html` 的 `const PIC_MAP`，并做覆盖率统计 |
| `check_pic_map.js`（在 `tests/`） | 编译结果的结构校验 + 真浏览器渲染校验 |

## 怎么用

```bash
cd ~/.agents/skills/自学英语
python3 tools/pics/build_pic_map.py            # 写进 index.html + 打印覆盖率
python3 tools/pics/build_pic_map.py --check    # 只校验 index.html 里的是不是最新
```

## 🔴 三条规矩

1. **不许动 `EMOJI_MAP`**。那是「看图猜词」游戏的数据源，`renderEmojiQ` 按它筛词、
   选项去重也依赖它；翻卡配图是另一件事，所以另开 `PIC_MAP`。
2. **不认识的词宁可留空，也不许硬凑**。给「however」贴一张门 🚪 会教出错误联想，
   比没有图更糟。没图的词卡片就照旧居中显示，不留空框、不裂版。
3. **孤儿键直接报错**。`pic_map.json` 里的词必须在 `VOCAB` 里真实存在（含大小写），
   拼错一个字母就会静默失效，所以让脚本替我们喊出来。

## 🔴 图什么时候出现（老曾 2026-09-20 追加的要求）

> "调整下，当我没有点卡片显示中文的时候图片先不要出来"

**图片是"答案"的一部分**：`renderFlashcard()` 把 emoji 塞进 `#fc-pic` 之后**立刻藏起来**，
只有 `toggleCn()`（用户点卡片翻开中文）和 `markUnknown()`（点「不熟」自动翻答案）才调
`setPicVisible(true)`；收起中文时一起收回去。
**没翻之前连图框都不许占位置**——单词照旧居中，别提前把答案漏出来。
